# Extraction and Synthesis Status

This ZIP is a **standalone coherent API project**, not a partial patch to Infinite Domain.

Included in the seed and first synthesis pass:

- Python API/CLI/HTTP contracts;
- portable JSON-Schema AI tool catalog;
- local mod/namespace discovery;
- vanilla-first registry fallback policy;
- deterministic Minecraft structure NBT reader/writer;
- target-version compatibility profiles for common modding releases;
- geospatial/worldgen helper contracts;
- graded audit/refit/rebuild levels;
- cultural/theme/purpose models;
- physical and security clearance models;
- mechanical/fitness evaluation;
- immutable snapshot/resume system;
- generated-artifact snapshot storage with hashes;
- independent visual-review doctrine;
- generational scripting doctrine;
- original modular dungeon/spatial-layout generator;
- triple-fold macro/meso/micro modularity;
- purpose-driven size and functional-zone fitness gates;
- deterministic dungeon-to-Minecraft-NBT architectural skeleton materialization;
- version-aware automatic fragmentation into fixed-offset NBT piece sets;
- generator-provider registry for future settlements, infrastructure, jigsaw, schematic, and project-specific systems;
- classic donjon-option compatibility translation without linking the upstream runtime;
- isolated donjon reference/fetch path with explicit CC BY-NC boundary;
- CI and unit tests;
- Infinite Domain extraction/provenance manifest and selected agent-reference patterns.

Intentionally not bundled or not yet implemented:

- Infinite Domain generated NBT binaries;
- Infinite Domain quest data, loot tables, factions and narrative content;
- copyrighted/imported donor structure corpora;
- mod JARs;
- font/image/texture assets;
- a project-wide license that has not been explicitly chosen;
- a 1.12 numeric palette materializer;
- finished architectural/detail providers for every structure class;
- full jigsaw-pool compiler/runtime assembly provider;
- fixed-camera render implementation and in-game runtime placement harness.

Those remaining items are either consuming-project data or later reusable capability layers rather than reasons to fork the authoritative workflow.
