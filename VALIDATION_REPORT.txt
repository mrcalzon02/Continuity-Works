Candidate transport completed this cycle
----------------------------------------
ContinuityWorksDecisionAuthorityAdapter now exposes decisionCandidates(...) and applyCandidateDecision(...) as transport-facing delegation methods. Both require an exact observed decision revision before delegating to ContinuityWorksCompactBlueprintApi; the adapter does not duplicate candidate legality, dictionary fingerprinting, or mutation semantics.

ContinuityWorksDecisionAuthorityHttpServer now exposes two additional authoritative operations under the existing decision service:
- POST /v1/blueprints/decision/candidates
- POST /v1/blueprints/decision/apply-candidate

The Java transport stores the original BlueprintRequest beside each active decision state so candidate discovery uses the same authoritative request context captured at begin. A restoreDecision(request, state) overload preserves that invariant for later persistence/resume integration. The previous restoreDecision(state) seam remains backward-compatible but cannot fabricate missing request context for dynamic candidate discovery.

The Java service also:
- reports whether a dynamic candidate source is configured
- serializes complete dictionary identity/source/revision/choice data
- reconstructs transported dictionaries through the authoritative Dictionary record, rechecking fingerprint integrity
- rejects a dictionary whose bound revision no longer matches the current authoritative decision with HTTP 409 stale_candidate_dictionary
- continues using compare-and-replace state advancement so concurrent stale inference output cannot overwrite newer state
- preserves all existing profile/begin/next/apply/validate/finalize routes and constructors

Python delegated publication bridge
-----------------------------------
The existing Python service remains a transport proxy and does not parse, rank, resolve, validate, or recreate candidate dictionary semantics. When a separate Java authority is configured it now advertises and transparently proxies:
- /v1/blueprints/decision/candidates

The same two routes are included in conditional OpenAPI publication and executable discovery metadata. When no Java authority is configured, decision routes remain unpublished/unavailable rather than falling back to a Python decision implementation.
