Visual rendering/review boundary
--------------------------------
- Continuity Works does not require server-side visual rendering as part of generation.
- fitness.visual_gate is OPTIONAL_CLIENT_REVIEW.
- fitness.visual_review_required is false.
- fitness.visual_review_owner is client.
- fitness.server_side_rendering is false.
- StructureCapability advertises visual_review.required=false and independent_visual_review_required=false.
- Generation provider contracts advertise server_visual_review_required=false,
  server_side_rendering=false, client_rendering_responsibility=true, and
  visual_review_advisory_only=true.
- StructureForge is the reference browser-side renderer; other clients render returned
  geometry/artifacts using compute they control when visual inspection is desired.
- Absence of a render or visual review does not block generation, validation, snapshotting,
  or response delivery.

Deployment/hosting boundary
---------------------------
PUBLIC HTTPS SERVICE: NOT CLAIMED LIVE.

The repository contains an optional reference render.yaml using the Continuity Works name
and free plan. It does not create an account, authorize billing, or require the project owner
to provide open public compute. Consumers may run Continuity Works locally or on infrastructure
they control. A configured candidate URL is not treated as a live service until remote acceptance
actually succeeds against it.

The external workflow publishes continuity-works/public-serviceability only when a configured
remote API genuinely serves the expected commit and the Pages-to-API discovery chain passes.
Local validation deliberately cannot grant that external VERIFIED state.

Intentional boundaries
----------------------
- GitHub Pages is the static StructureForge client and is never treated as Python execution proof.
- No server-side rendering obligation is created by the public API contract.
- Upstream donjon dungeon.pl remains isolated under its existing licensing boundary.
- Minecraft 1.12.x retains the existing legacy materialization limitation.
- Runtime/mechanical validation requirements remain intact.
- Compatibility with other mods/systems remains additive and non-destructive.
