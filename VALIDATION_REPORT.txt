The implementation deliberately does not invent canonical biome, culture, condition, palette, or catalog values that authoritative data does not yet publish. Dynamic mutators receive values from a caller-supplied authoritative BlueprintDecisionCandidateSource. Fixed mutators derive choices from the existing mutator metadata.

Candidate integrity and compression behavior:
- maximum 256 choices per dictionary
- authoritative source snapshots carry an explicit sourceVersion
- each dictionary is bound to protocol version, request UUID, exact decision revision, mutator code, source version, and ordered choices
- deterministic SHA-256 dictionary identity covers all bound fields and choices
- tampered dictionary identity fails closed
- compact local choice codes use deterministic uppercase base-36 indexes
- provider candidates are dry-run through the existing BlueprintDecisionChain.apply parser before dictionary publication, preventing candidate providers from widening semantic wire legality
- a dictionary cannot bypass mutator dependencies
- protocol mismatch, request mismatch, stale revision, invalid local code, duplicate source values, invalid semantic values, and fingerprint tampering fail closed
- local choice codes are resolved back to authoritative semantic values before BlueprintDecisionChain.apply executes
- finalized BlueprintSpecifications therefore contain semantic identities, never ephemeral local codes
- state-bound correction dictionaries may revise an already-selected mutator when its dependencies remain valid; downstream invalidation is still performed by the existing authoritative decision chain

The Java 17 behavioral harness verifies provider-fed archetype choices, deterministic local codes, semantic resolution, stale-dictionary rejection, fixed SCALE choices from mutator metadata, source-version-sensitive identities, BIOME candidate binding, required-state finalization, correction dictionaries, dependency rejection, duplicate rejection, invalid-wire rejection, and fingerprint tamper rejection.
