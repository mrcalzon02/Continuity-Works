Source-version and stale-dictionary integrity
---------------------------------------------
EraStructureCatalogCandidateSource derives sourceVersion from SHA-256 of the exact UTF-8 ledger snapshot using the prefix cw-era-ledger-sha256:. No separate manual catalog-version constant is required.

Consequences:
- a byte change in the authority snapshot changes sourceVersion;
- candidate dictionaries inherit that content-derived sourceVersion;
- existing dictionary identity therefore changes when the authoritative ledger snapshot changes;
- local compact choice codes remain ephemeral and resolve back to semantic catalog IDs before mutation;
- the provider only answers the STRUCTURE_CATALOG archetype mutator and rejects archetype-profile mutators;
- request/state identity must match;
- a ledger snapshot with no materialized hero-spec rows fails closed.

This is intentionally one-way authority flow: ledger -> candidate source -> state-bound dictionary -> semantic decision chain. The candidate source cannot widen mutation wire legality because BlueprintDecisionCandidates still dry-runs candidate values through BlueprintDecisionChain.apply before publishing a dictionary.
